# Chat autocomplete

Type `#` followed by at least two characters to search inventory IDs/descriptions. Type `*` to search customer names/IDs. Select with arrows and Enter or click/tap. Escape closes the list. Confirmed selections appear as removable chips; editing the token clears its selection. Plain names and IDs remain supported without markers. One item and one customer per request; batch pricing is deferred.

`GET /v1/Chat/lookups?kind=item|customer&q=...` requires an authenticated sales-capable IMP user and the signed-in Acumatica token. It returns at most eight metadata records. Separate per-user limit:90/minute per process. HTTP results are no-store. Active StockItem, NonStockItem and Customer metadata expires after 30 minutes unless successfully refreshed. The bounded process cache is isolated by user, role and OAuth session. No prices, notes, tokens or ownership grants are cached. Cold catalogs can take several seconds; subsequent typing searches cached metadata. A failed load after hard expiry is reported as unavailable, never served as an expired catalog.

At container launch, a hosted worker loads both complete metadata catalogs using the existing server integration credentials in a dedicated read-only session, explicitly bound to the current OAuth tenant. It logs only record counts, logs out, refreshes every 20 minutes and retries failures after one minute. Failed refreshes do not stop the API or extend the hard 30-minute expiry. The cached fields are only kind, ID, name/description and unit: no price, note or permission records.

Suggestions search that shared metadata, then verify the current login/tenant and re-read only matching candidate rows using the signed-in user's own Acumatica token. Customer queries include Salespersons so Sales ownership and ERP record visibility are checked live before names are disclosed. This replaces the previous scan of every customer assignment on each keystroke. Candidate checks are bounded to 80 matches in batches of 40; broader queries ask for narrower input. Active status and returned identity are checked again. Item visibility is also verified through the user's own token.

The browser calls authenticated `POST /v1/Chat/lookups/warm` after login/session restore without waiting to open chat. When startup catalogs are ready it immediately returns 204 with no records and does not reload them. If startup preload is unavailable, the existing per-user/role/OAuth-session cache and login warmup remain fallback. Visible tabs retry every 20 minutes; hidden tabs catch up on return and sign-out aborts old requests. It makes no LLM calls. Customer ownership and final selected IDs are never authorized from cached metadata.

Azure Container App `imp-dev-ca` is configured for minimum 1 replica (maximum 3), at the existing 0.5 vCPU / 1 GiB size. ACR Basic remains an image registry and is not an always-running application host. Each new replica launches its own metadata preload and refresh worker, including after restart or scale-out. There is a short initial load window; login preload is a fallback. No Redis is required. Shared metadata never grants access to a customer, item, price or note.

Signed-in ERP reads use the named `AcumaticaBearer` HTTP client with cookies and automatic redirects disabled. They must not inherit cookies from the default integration-session HTTP pool. A candidate request returning 401 or a login redirect is treated as an expired session; 403 remains an access denial. Invalid payloads and scope mismatches remain unavailable rather than being treated as empty results. Diagnostic logs include only the failure category and controlled scope reason, without tokens or returned record payloads.

Sales login and explicit salesperson mapping are verified; current assigned customer IDs are read on EVERY customer suggestion request. Unassigned customers are filtered before ranking/limiting/disclosure. Metadata caching never grants customer access. Submission carries selected kind/ID alongside the marked question; the server checks token presence and live identity/ownership, strips only verified markers, and uses the selected IDs for pricing. Existing tool ownership guards remain enforced. No new SQL schema, Redis, embedding model or vector database.

Tests cover debounce, stale responses, keyboard/IME, literal text, removable/edited chips, structured submission, cache single-flight/session isolation, ownership revocation, forged selections and HTTP denial. Read-only live catalog check:688 active customers and4,223 active items in this tenant (2026-10-23). Catalog counts and labels are not authorization grants.
